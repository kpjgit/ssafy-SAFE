# Unity 웹 스트리밍 구현 방식

Unity 시뮬레이터 화면을 웹 브라우저에 실시간으로 스트리밍하는 **직접 구현한 방식**을 자세히 정리한 문서입니다.

## 🎯 구현 목표

**"Unity 시뮬레이터 화면을 웹 브라우저에서 실시간으로 보기"**

- Unity Editor에서 실행 중인 시뮬레이터 화면을 웹에서 실시간으로 확인
- 웹에서 Unity 카메라 시점을 자유롭게 변경 가능
- Unity가 백그라운드로 가도 웹에서 계속 동작

## 🔧 핵심 구현 방식

### 1. Unity → Web 실시간 스트리밍 방식

**"HTTP 기반 JPEG 스트리밍"** 방식을 선택했습니다.

#### 왜 이 방식을 선택했나?
- **WebSocket**: Unity에서 WebSocket 서버 구현이 복잡
- **HTTP**: Unity 내장 HttpListener 사용 가능, 구현 간단
- **JPEG**: 실시간 압축, 브라우저 호환성 좋음
- **Canvas**: HTML5 Canvas로 이미지 렌더링

## 🏗️ 직접 구현한 아키텍처

```
┌─────────────────┐    HTTP/JPEG    ┌─────────────────┐
│   Unity Editor  │ ──────────────► │  Web Browser    │
│                 │                 │                 │
│ ┌─────────────┐ │                 │ ┌─────────────┐ │
│ │   Camera    │ │                 │ │   Canvas    │ │
│ │ RenderTexture│ │                 │ │   React     │ │
│ └─────────────┘ │                 │ └─────────────┘ │
│ ┌─────────────┐ │                 │ ┌─────────────┐ │
│ │HTTP Server  │ │                 │ │ Fetch API   │ │
│ │JPEG Encoder │ │                 │ │ Image Load  │ │
│ └─────────────┘ │                 │ └─────────────┘ │
└─────────────────┘                 └─────────────────┘
```

### 데이터 흐름 (직접 구현한 방식)
1. **Unity Camera** → **RenderTexture** (GPU 렌더링)
2. **RenderTexture** → **Texture2D** (CPU로 픽셀 읽기)
3. **Texture2D** → **JPEG** (실시간 압축)
4. **JPEG** → **HTTP Response** (웹으로 전송)
5. **HTTP Response** → **Canvas** (브라우저에서 렌더링)

## 🔧 직접 구현한 핵심 기술

### 1. Unity HTTP 서버 구현 (UnityHttpVideoServer.cs)

**직접 작성한 스크립트**로 Unity 내에서 HTTP 서버를 구동합니다.

#### 핵심 설정값 (요약)
- 포트: 8081
- 해상도: 1280x720
- FPS: 30 (최적화 시 60)
- JPEG 품질: 70~80

#### 서버 시작 로직 (요약)
- HttpListener로 `/unity-video/` 프리픽스 등록 후 비동기 루프 실행
- 메인 스레드 블로킹 없이 백그라운드에서 요청 처리

**왜 이렇게 구현했나?**
- **포트 8081**: 다른 서비스와 충돌 방지
- **해상도 1280x720**: 웹에서 보기 적당한 크기
- **FPS 30**: Unity 성능과 웹 대역폭의 균형
- **JPEG 품질 80**: 압축률과 화질의 최적점

### 2. 실시간 프레임 캡처 (직접 구현한 방식)

**Unity 카메라 화면을 실시간으로 캡처하여 JPEG로 변환**하는 과정입니다.

#### 프레임 업데이트 (요약)
- RenderTexture → Texture2D 읽기 → JPEG 인코딩 → 메모리에 보관
- 타겟 FPS에 맞춰 반복 수행

**직접 구현한 이유:**
- **RenderTexture**: GPU에서 렌더링하여 성능 최적화
- **ReadPixels**: CPU로 픽셀 데이터를 읽어서 JPEG 변환 가능
- **EncodeToJPG**: Unity 내장 압축으로 빠른 처리
- **코루틴**: Unity 메인 스레드를 블록하지 않으면서 프레임 제어

### 3. HTTP 엔드포인트 구현 (직접 작성한 API)

**웹에서 Unity와 통신하기 위한 REST API**를 직접 구현했습니다.

#### 프레임 제공 API (요약)
- `GET /unity-video/frame`: 최신 JPEG 단일 프레임 반환

#### 카메라 목록 API (요약)
- 필요 시 `GET /unity-video/camera/list`로 카메라 목록 제공 (프로젝트 설정에 따라 사용)

#### 카메라 전환 API (요약)
- 필요 시 `POST /unity-video/camera/switch`로 전환 (프로젝트 설정에 따라 사용)

**직접 구현한 API 엔드포인트:**
- `GET /unity-video/frame` - 실시간 프레임 이미지
- `GET /unity-video/camera/list` - 사용 가능한 카메라 목록
- `POST /unity-video/camera/switch` - 카메라 전환

### 4. React 프론트엔드 구현 (UnityHttpVideoStream.tsx)

**직접 작성한 React 컴포넌트**로 Unity 스트림을 웹에서 표시합니다.

#### 컴포넌트 인터페이스 (직접 설계)
```typescript
interface UnityHttpVideoStreamProps {
  streamUrl: string;              // Unity HTTP 서버 URL
  autoPlay?: boolean;             // 자동 재생 여부
  showCameraControls?: boolean;   // 카메라 제어 버튼 표시
  className?: string;            // CSS 클래스
}
```

#### 프레임 요청 로직 (직접 구현)
```typescript
const requestFrame = async () => {
  try {
    // Unity HTTP 서버에서 프레임 요청
    const response = await fetch(`${streamUrl}/frame`, {
      method: 'GET',
      cache: 'no-cache',           // 캐시 비활성화 (실시간)
      signal: AbortSignal.timeout(5000)  // 5초 타임아웃
    });
    
    // 응답을 Blob으로 받기
    const blob = await response.blob();
    const img = new Image();
    
    // 이미지 로드 완료 시 Canvas에 그리기
    img.onload = () => {
      canvas.width = img.width;
      canvas.height = img.height;
      ctx.drawImage(img, 0, 0);
    };
    
    // Blob을 이미지 URL로 변환
    img.src = URL.createObjectURL(blob);
  } catch (error) {
    // 에러 발생 시 재시도 (연결 끊김 방지)
  }
};
```

#### 실시간 업데이트 (직접 구현)
```typescript
useEffect(() => {
  if (autoPlay) {
    // 첫 프레임 요청
    requestFrame();
    
    // 200ms마다 프레임 요청 (5fps)
    intervalRef.current = setInterval(requestFrame, 200);
  }
  
  return () => {
    if (intervalRef.current) {
      clearInterval(intervalRef.current);
    }
  };
}, [streamUrl, autoPlay]);
```

**직접 구현한 이유:**
- **5fps 요청**: Unity는 30fps로 캡처하지만 웹은 5fps로 요청 (대역폭 절약)
- **타임아웃 5초**: 네트워크 문제 시 빠른 복구
- **캐시 비활성화**: 실시간 이미지 보장
- **메모리 정리**: URL.revokeObjectURL로 메모리 누수 방지

### 5. 카메라 제어 시스템 (직접 구현)

**웹에서 Unity 카메라를 실시간으로 전환**할 수 있는 시스템을 직접 구현했습니다.

#### Unity 카메라 관리 (직접 설정)
```csharp
[Header("Camera Settings")]
public bool enableCameraSwitching = true;  // 카메라 전환 기능 활성화
public Camera[] availableCameras;           // 사용 가능한 카메라 배열
public string[] cameraNames;               // 카메라 이름 배열
public int currentCameraIndex = 0;        // 현재 선택된 카메라 인덱스
```

#### 웹에서 카메라 전환 (직접 구현)
```typescript
const switchCamera = async (cameraIndex: number) => {
  try {
    // Unity HTTP 서버에 카메라 전환 요청
    const response = await fetch(`${streamUrl}/camera/switch`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ cameraIndex })
    });
    
    if (response.ok) {
      // 성공 시 현재 카메라 인덱스 업데이트
      setCurrentCameraIndex(cameraIndex);
    }
  } catch (error) {
    console.error('카메라 전환 실패:', error);
  }
};
```

#### 카메라 목록 가져오기 (직접 구현)
```typescript
const fetchCameraList = async () => {
  try {
    const response = await fetch(`${streamUrl}/camera/list`);
    const data = await response.json();
    setAvailableCameras(data.cameras);
  } catch (error) {
    console.error('카메라 목록 가져오기 실패:', error);
  }
};
```

**직접 구현한 카메라 제어 기능:**
- **실시간 전환**: 웹에서 버튼 클릭으로 즉시 카메라 변경
- **다중 카메라**: 여러 카메라를 배열로 관리
- **상태 동기화**: 웹과 Unity 간 카메라 상태 동기화
- **에러 처리**: 전환 실패 시 적절한 에러 메시지

## 🚀 직접 구현한 성능 최적화

### 1. 백그라운드 실행 (직접 해결)
**문제**: Unity가 백그라운드로 가면 웹에서 동작이 멈춤
**해결**: `Application.runInBackground = true` 설정

설정: `Application.runInBackground = true` (백그라운드 실행 유지)

### 2. 프레임 레이트 제어 (직접 최적화)
**Unity 측**: 30fps로 캡처 (성능과 품질의 균형)
**Web 측**: 5fps로 요청 (대역폭 절약)

```typescript
// 200ms마다 프레임 요청 (5fps)
intervalRef.current = setInterval(requestFrame, 200);
```

### 3. 메모리 관리 (직접 구현)
**문제**: 이미지 URL이 계속 생성되어 메모리 누수 발생
**해결**: 사용 후 즉시 메모리 정리

```typescript
// 메모리 정리
URL.revokeObjectURL(img.src);
```

### 4. 에러 복구 (직접 구현)
**문제**: 네트워크 요청이 중복되거나 실패 시 처리
**해결**: 요청 상태 관리 및 자동 재시도

```typescript
// 요청 중복 방지
if (isRequestingRef.current) {
  return;
}
isRequestingRef.current = true;
```

### 5. JPEG 품질 최적화 (직접 설정)
**품질 80%**: 압축률과 화질의 최적점
- **품질 100%**: 파일 크기 너무 큼
- **품질 60%**: 화질 저하
- **품질 80%**: 적당한 크기와 화질

## 📊 직접 구현한 데이터 흐름

### 1. Unity → Web 스트리밍 (실시간 이미지 전송)
```
Unity Camera → RenderTexture → Texture2D → JPEG → HTTP Response → Web Canvas
     ↓              ↓              ↓           ↓           ↓            ↓
   카메라 렌더링   GPU 텍스처    CPU 픽셀    압축된      웹으로        브라우저
                  생성          읽기        이미지      전송          표시
```

### 2. Web → Unity 제어 (카메라 전환)
```
Web Button → Fetch API → HTTP Request → Unity Server → Camera Switch
     ↓           ↓            ↓              ↓             ↓
   사용자      HTTP 요청    POST 데이터    서버 처리    카메라 변경
   클릭        전송         수신           실행         완료
```

### 3. 실제 구현 과정 (단계별)
1. **Unity에서 HTTP 서버 시작** (포트 8081)
2. **카메라를 RenderTexture에 렌더링** (30fps)
3. **픽셀 데이터를 JPEG로 압축** (품질 80%)
4. **웹에서 200ms마다 프레임 요청** (5fps)
5. **Canvas에 이미지 그리기** (실시간 표시)
6. **카메라 전환 요청 시 즉시 변경** (POST API)

### 1. 실시간성 (직접 구현)

- **자동 복구**: 연결 끊김 시 자동 재시도 (5초 타임아웃)

- **멀티 카메라**: 여러 카메라를 배열로 관리
- **해상도 조정**: 1280x720으로 최적화
- **프레임 레이트**: Unity 30fps, Web 5fps로 최적화

### 3. 호환성 (직접 검증)
- **브라우저 지원**: Chrome, Firefox, Safari, Edge
- **플랫폼 독립**: Windows, Mac, Linux
- **모바일 지원**: 반응형 디자인 (Tailwind CSS)

### 4. 성능 (직접 최적화)
- **메모리 효율**: URL.revokeObjectURL로 메모리 누수 방지
- **CPU 효율**: Unity 코루틴으로 메인 스레드 블록 방지
- **네트워크 효율**: JPEG 압축으로 대역폭 절약

## 🔧 직접 해결한 문제들

### 실제 발생한 문제들
1. **포트 충돌**: 8081 포트가 이미 사용 중

2. **카메라 렌더링**: Unity Game View에서 화면이 검정색
   - **해결**: 카메라 설정 확인 및 RenderTexture 설정
3. **네트워크**: 방화벽에서 Unity HTTP 서버 차단
   - **해결**: 방화벽 설정에서 포트 8081 허용
4. **성능**: Unity가 백그라운드로 가면 웹에서 멈춤
   - **해결**: Application.runInBackground = true 설정

## 🚀 최신 업데이트 (2024년 12월)

### 요약
- Unity, Python 모두 **MJPEG 스트림** 추가로 브라우저에서 `<img>` 만으로 실시간 재생.
- 폴링 제거 → 지연시간 감소, 부드러운 재생(체감 30fps+), 코드 단순화.

### 변경 사항 (프론트엔드)
- `front/src/components/UnityHttpVideoStream.tsx`
  - Canvas + fetch 폴링 → `<img src="{streamUrl}/stream.mjpg">`로 단순화
  - 연결 상태/표시 최소화, MJPEG 자동 갱신 활용
- `front/src/components/VideoStream.tsx`
  - Python 측도 MJPEG(<img>) + Canvas 오버레이(포즈) 유지

### 변경 사항 (서버)
- Unity: `GET /unity-video/stream.mjpg` 추가, 30~60fps JPEG 푸시
- Python: `GET /stream.mjpg` 제공, NDJSON은 stdout 유지, 필요 시 `POST /python-video/frame` 지원

### 엔드포인트
- Unity: `/unity-video/frame`, `/unity-video/stream.mjpg`, `/unity-video/status`
- Python: `/stream.mjpg`, `/python-video/frame`

### 성능(요약)
- 지연시간: 폴링 대비 크게 감소(≈50–100ms)
- 프레임: 브라우저 기준 안정적 30fps 수준
- 부하: 브라우저 CPU 3–5%대, 네트워크 300–600KB/s(해상도·품질에 따라 상이)

### 사용 방법(간단)
1) Unity 실행 → 콘솔의 `.../unity-video/stream.mjpg` 확인
2) React 앱 실행 → 좌측 Unity 패널이 자동 재생됨
3) Python 실행(선택) → `/stream.mjpg`를 우측 패널에서 `<img>`로 표시
